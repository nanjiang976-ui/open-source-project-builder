# 项目类型与发布检查

先用一句话补完“这个人带着什么来，成功时能看到什么”。读者各有不同入口时，把主要读者的路径放在首页，其他路径给清楚的链接。下表帮助选择要查的证据；目录名沿用实际仓库。

| 项目形态 | 首页带读者做什么 | 查哪些证据 |
|---|---|---|
| Agent Skill | 在支持的客户端安装，打开目标项目，说一句能触发它的话，辨认回答 | 包里的技能目录、直接位于其中的 `SKILL.md`、支持的客户端、真实输入与结果。区分仓库首页给人的说明和 Skill 给 Agent 的指令 |
| 命令行工具 | 选对平台下载或安装，在明确的目录跑一条命令，从退出状态、文件或输出判断成功 | 包管理器声明或实际发布文件、命令名、参数、示例输入和输出；有多个安装方式时说明首选项 |
| 开发库 / SDK | 安装兼容版本，执行最短调用，看到返回值 | 包名与导入名、版本要求、示例、测试。用到外部服务时说明凭据和费用条件 |
| 桌面应用 / 扩展 | 选择安装包或商店入口，完成一次界面操作 | 支持系统、下载地址、界面入口、可见产物；开发者构建流程单独给入口 |
| 自部署应用 | 准备环境和配置，启动服务，打开页面验证 | 示例配置与必填项、运行时或容器清单、访问地址、首次登录；持久化重要数据时说明保存位置和备份 |
| 模板 | 从模板得到可改的项目，替换必要内容并成功运行 | 模板自身说明与交付给新项目的文件、实际占位项、生成后的工作目录及验证命令 |
| 教程 / 资料库 | 找到第一项任务或资源，完成练习或引用素材 | 示例输入、完成标志、素材来源及许可、贡献入口；各项资源的权利可能不同 |

## 组织首次发布

- **读者能找到入口。** 用一句话说明用途，给一个真实输入和可识别的结果。前提条件写在读者即将用到的位置。
- **首次使用能复现。** 用交付给读者的那一份文件或发布包走安装、发现与首次调用。仓库源码能跑、发布包能安装和桌面端能操作要分别记证据。
- **知道哪些材料可以公开和复用。** 查项目许可、第三方代码与素材、示例配置及拟发布内容。缺少决定时留下待作者确认项，公示准备也要检查可能随提交历史带出的内容。
- **反馈能找到作者。** 优先采用项目真实可用的入口，写清反馈时需要的最少信息。收到外部贡献之后，按实际维护方式补贡献说明和问题模板。
- **更新有据可查。** 发新版时对照旧 README 和本次变动，复跑受影响的首次路径。在发布说明中记录兼容性变化和已知局限。较长的教程、FAQ 或路线图按读者需求拆分。
